# RECA-PD benchmark integration

This directory contains the minimum RECA-PD code used for the benchmark experiments.

The integration retains the RECA-PD model, data loader, training and threshold inference pipelines, feature definitions, and feature extraction scripts. Old protocols, regression experiments, analysis notebooks, logs, checkpoints, and unused model variants are excluded.
The inherited model implementation is distributed under the MIT license in `reca_pd/LICENSE` and retains the upstream copyright notice.


## 1. Install

Use Python 3.10. Install the Python packages and the system program required by DisVoice:

```bash
pip install -r reca_pd/requirements.txt
sudo apt-get install praat
```

Install a PyTorch build appropriate for the machine's CUDA version if the pinned wheel is not suitable.

## 2. Extract features

For every dataset directory, the input WAV files must be directly under `audios_fortrain/`. Run both extractors from the repository root:

```bash
AUDIO_DIR="/path/to/dataset/audios_fortrain"
FEATURE_DIR="/path/to/dataset/speech_features"

python3 reca_pd/scripts/feature_extraction/extract_disvoice_features.py \
  --wav-dir "$AUDIO_DIR" \
  --output-dir "$FEATURE_DIR" \
  --num-jobs 4

python3 reca_pd/scripts/feature_extraction/extract_wav2vec_features.py \
  --wav-dir "$AUDIO_DIR" \
  --output-dir "$FEATURE_DIR"
```

This produces the layout expected by the data loader:

```text
dataset/
├── audios_fortrain/
└── speech_features/
    ├── disvoice/
    │   ├── articulation/
    │   ├── glottal/
    │   ├── phonation/
    │   └── prosody/
    └── wav2vec/
        └── layer07/
```

Each feature file must have the same basename as its WAV and use the `.npz` extension. The filelists must point to paths containing the directory name `audios_fortrain`; the loader derives feature paths by replacing that directory component with the paths above.

## 3. Check audio and features

After generating the local filelists, check every WAV and feature file required by the experiment you plan to run:

```bash
python3 reca_pd/scripts/feature_extraction/check_features.py \
  --splits-dir "/path/to/runtime_splits" \
  --regime all \
  --report "/path/to/reca_pd_feature_audit.json"
```

Use `all`, `all_subset`, `early`, `early_private`, or `all_stage` to match the launcher. A successful check reports zero `split_errors`, `audio_errors`, and `feature_errors`. The WAV check requires non-empty mono, 16 kHz, 16-bit PCM audio. The feature check requires a non-empty `.npz` file for Wav2Vec layer 07 and each of the four DisVoice feature groups.

Inspect the JSON report before training if the command exits with an error.

## 4. Experiment settings

All experiments use five folds and five seeds.

| Launcher | Training set | Validation and test set | Meaning |
|---|---|---|---|
| `run_5seeds_all.sh` | `train.tsv` | EarlyPD | AllPD |
| `run_5seeds_allsubset.sh` | `train_allPDsubset.tsv` | EarlyPD | AllPD-subset |
| `run_5seeds_early.sh` | `train_earlybalance.tsv` | EarlyPD | EarlyPD only |
| `run_5seeds_earlypersp.sh` | `train_early_persp.tsv` | EarlyPD | EarlyPD + private data |
| `run_5seeds_allPDval.sh` | `train.tsv` | All-stage PD | Stage-level experiment using AllPD for training, validation, and test |

All launchers use seeds 42–46 by default.

## 5. Run training

The small wrapper scripts select an experiment setting and call the shared `run_5seeds.sh` launcher. For a public setting, the launcher runs DDK, sustained vowel, and Sentence in sequence; within each task it runs five independent seeds and all five folds. For example, `run_5seeds_all.sh` produces 3 tasks × 5 runs × 5 folds. The Private track runs DDK and sustained vowel only.

Use the local splits generated by `benchmark_tools/prepare_splits.py`:

```bash
SPLITS_ROOT="/path/to/runtime_splits" \
CUDA_VISIBLE_DEVICES=0 \
bash reca_pd/runs/run_5seeds_all.sh
```

Replace the launcher with the required experiment. Outputs default to:

```text
outputs/reca_pd/<regime>/<task>/run_<1-5>/fold_<1-5>/
```

The training pipeline selects the best checkpoint by validation ROC AUC, tunes a positive-class probability threshold on validation by positive-class F1, and applies that threshold to test probabilities. The output TSV stores this score in the `probability` column.

To inspect all commands and verify split paths without starting training:

```bash
DRY_RUN=1 SPLITS_ROOT="/path/to/runtime_splits" \
  bash reca_pd/runs/run_5seeds_all.sh
```

## 6. Add private training data

RECA-PD can augment the EarlyPD training condition with a private cohort. Private recordings are used for training only: the public EarlyPD validation and test lists remain unchanged. The paper's private-data setting covers DDK and sustained vowel; it does not run Sentence because there is no corresponding private Sentence training list.

If a different private cohort is used, the experiment follows the same protocol but does not reproduce the paper's private-data number exactly.

### Prepare the private recordings

Preprocess private WAV files into `audios_fortrain/` and extract the five feature groups described in [Extract features](#2-extract-features). Use globally unique speaker IDs so they cannot collide with NeuroVoz or PC-GITA IDs.

Create one TSV per supported task:

```text
ID	AUDIOFILE	DIAGNOSIS
PRIVATE_001	/path/to/private/audios_fortrain/PD_DDK_PRIVATE_001.wav	Parkinson
```

Both files must contain `ID`, `AUDIOFILE`, and `DIAGNOSIS`. `DIAGNOSIS` must be `Healthy` or `Parkinson`. Multiple recordings may share one speaker ID, but each `AUDIOFILE` must be unique.

### Generate the augmented training lists

The generator starts from each fold's public `train_earlybalance.tsv`, appends the task-matched private rows, and writes `train_early_persp.tsv` under a separate root:

```bash
python3 reca_pd/scripts/prepare_private_training_splits.py \
  --splits-dir "/path/to/runtime_splits" \
  --private-ddk "/path/to/private_ddk.tsv" \
  --private-vowel "/path/to/private_vowel.tsv" \
  --output-dir "/path/to/private_training_splits"
```

It rejects duplicate recordings, conflicting labels, and any private speaker or audio path that overlaps the public splits. All private rows are added to the training portion of every fold. The generated root contains only the training lists required by this setting:

```text
private_training_splits/
├── folds_tsv_DDK_ANALYSIS_PATAKA/
│   └── fold_1 ... fold_5/
│       └── train_and_val/train_early_persp.tsv
└── folds_tsv_SUSTAINED-VOWELS_onlyA123/
    └── fold_1 ... fold_5/
        └── train_and_val/train_early_persp.tsv
```

### Check and train

Check the public evaluation lists and augmented training lists together:

```bash
python3 reca_pd/scripts/feature_extraction/check_features.py \
  --splits-dir "/path/to/runtime_splits" \
  --train-splits-dir "/path/to/private_training_splits" \
  --regime early_private \
  --report "/path/to/private_feature_audit.json"
```

Then keep the two roots separate when launching training:

```bash
SPLITS_ROOT="/path/to/runtime_splits" \
TRAIN_SPLITS_ROOT="/path/to/private_training_splits" \
CUDA_VISIBLE_DEVICES=0 \
bash reca_pd/runs/run_5seeds_earlypersp.sh
```

`SPLITS_ROOT` supplies the fixed public validation and test lists. `TRAIN_SPLITS_ROOT` supplies only the augmented `train_early_persp.tsv` files.
